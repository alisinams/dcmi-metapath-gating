# Correcting connectivity bias in meta-path gating for heterogeneous graph neural recommender systems

Code, result files and figure scripts for the manuscript of the same title by
Mahdi Bazargani and Alisina Mousavi (Department of Computer Engineering, Islamic Azad University,
Zanjan Branch, Zanjan, Iran).

[![DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.23155898.svg)](https://doi.org/10.5281/zenodo.23155898)

## Overview

Heterogeneous recommenders must decide how much each meta-path (a typed relational route between users and
items) contributes to a representation, and a common shortcut weights meta-paths by subgraph density.
Density, and the raw mutual information often proposed instead, both reward connectivity. This repository
implements:

* **DCMI** (density-corrected mutual information): a plug-in mutual information estimate between the
  propagated neighbourhood signal of a meta-path and held-out interactions, referenced against an ensemble of
  40 degree-preserving surrogate graphs and reported as a z-score (`code/dcmi.py`);
* **MIDGaP**: a recommender whose learned meta-path gate is anchored to the DCMI prior by a
  Kullback-Leibler penalty and whose variational bottleneck is trained jointly with a ranking loss; the
  posterior also yields a per-user predictive variance (`code/models.py`);
* the full evaluation: nine baselines, full-catalogue ranking under a global-timeline split, gate-criterion
  and component ablations, a sampled-versus-full protocol study and the uncertainty analysis.

## Repository layout

| Path | Content |
|---|---|
| `code/` | Dataset construction, the DCMI estimator, every model, training and evaluation, tuning, ablations, the protocol and uncertainty studies, and the aggregation into tables (`tables.py`) |
| `figures/` | One script per manuscript figure, the shared style engine `sciviz.py`, `figcommon.py` and `build_all.py` |
| `figures/output/journal/` | The five figures as built for submission (PDF and PNG; EPS and TIFF are regenerated by `build_all.py`) |
| `cache/` | DCMI statistics per meta-path (`*_dcmi.json`) and fingerprints of the splits (`split_fingerprints.json`, `SHA256SUMS_splits.txt`); the rebuilt splits (`*.pkl`) are not tracked |
| `results/` | Every result file behind the tables and figures (see below) |
| `tools/verify_splits.py` | Checks that locally rebuilt splits are identical to the ones used for the reported numbers |
| `data/` | Raw downloads (not tracked) |

## Installation

The results were produced with Python 3.13.1, PyTorch 2.11.0 (CUDA 12.8) and one NVIDIA GeForce RTX 3090.

```bash
pip install -r requirements.txt
```

Install the PyTorch build that matches your CUDA version from https://pytorch.org if the default wheel does
not fit your machine. The DCMI estimator, the tables and the figures run on a CPU.

## Data

The raw datasets are public but are not redistributed here: the MovieLens terms of use do not permit
redistribution, and the other two distributors set their own terms. The scripts download them from the
original sources:

| Benchmark | Source |
|---|---|
| MovieLens-100K, MovieLens-1M | https://grouplens.org/datasets/movielens/ |
| HetRec 2011 Last.FM | https://grouplens.org/datasets/hetrec-2011/ |
| Amazon Reviews 2023, Video Games (5-core ratings and metadata) | https://amazon-reviews-2023.github.io/ |

```bash
python code/download.py          # MovieLens-100K, MovieLens-1M, HetRec 2011 Last.FM
python code/dl_amazon.py         # Amazon Reviews 2023, Video Games
python code/build.py             # splits, meta-path adjacencies and content features -> cache/*.pkl
python tools/verify_splits.py    # must print IDENTICAL or "SPLITS IDENTICAL" for every dataset
```

`build.py` is fully seeded. The splits rebuilt from freshly downloaded data were verified to be identical to
the ones behind every reported number; `tools/verify_splits.py` repeats that check on your machine.

## Reproducing the results

All scripts locate `data/`, `cache/` and `results/` relative to the repository root, so they can be run from
any directory.

The result files in `results/` and the statistics in `cache/*_dcmi.json` are the ones reported in the
manuscript; the commands below regenerate them. Scripts append to existing result files and skip runs that
are already recorded, so move the shipped files aside before a full rerun.

```bash
# DCMI statistics (40 surrogates per meta-path); recomputed only when cache/<dataset>_dcmi.json is absent
python code/precompute_dcmi.py ml100k ml1m lastfm amazon

# validation grid search, one stream per benchmark, then freeze the selected configurations
python code/tune.py --datasets ml1m   --out tune_a.jsonl
python code/tune.py --datasets lastfm --out tune_b.jsonl
python code/tune.py --datasets amazon --out tune_c.jsonl
python code/pick_cfg.py                                   # results/best_cfg.json

# main comparison, five seeds (Tables 3 and 7)
python code/run.py --datasets ml1m   --seeds 5 --out main_ml1m.jsonl
python code/run.py --datasets lastfm --seeds 5 --out main_lastfm.jsonl
python code/run.py --datasets amazon --seeds 5 --out main_amazon.jsonl
python code/refresh_hdgcn.py      # re-tunes and re-runs the two-stage InfoMax baseline under the minimum-epoch budget

# gate-criterion study and component ablation, three seeds (Table 6, Fig. 3)
for d in ml1m lastfm amazon; do
  python code/study.py --study gate --datasets $d
  python code/study.py --study comp --datasets $d
done

python code/analysis.py protocol --dataset ml100k --seeds 3      # sampled versus full-catalogue protocol (Table 4)
python code/analysis.py uncertainty --dataset ml1m --seeds 3     # uncertainty analysis (Fig. 5)
python code/time_dcmi.py                                         # offline cost of the estimator
python code/tables.py                                            # results/tables.json and results/numbers.json
python code/export_activity.py                                   # training activity per user (for Fig. 4)
python figures/build_all.py                                      # all figures, strict quality checks
```

Seeds 0 to 4 are used for the main comparison and seeds 0 to 2 for the ablations and studies; the two
deterministic rankers (MostPop and ItemKNN) run once. Running `code/tables.py` on the shipped result files
reproduces every table and every number quoted in the manuscript. `analysis.py sensitivity` implements a
bottleneck-weight sweep that was not run for the manuscript, and no result of it is reported.

## Figures

`python figures/build_all.py` rebuilds the five figures from `results/` and `cache/*_dcmi.json` without a GPU.
Each figure passes automated checks for text overlap, legend placement, minimum printed font size (7 pt at
174 mm) and palette compliance before it is exported. Outputs in `figures/output/`:

* `journal/Fig<n>.{pdf,eps,tif,png}`: 174 mm wide, vector files with embedded TrueType fonts, rasters at 600 dpi;
* `masters/Figure_<n>_{white,transparent}.{pdf,tiff,png}`: design-size masters;
* `figure_captions.json`, `fig<n>_values.json`: captions and every plotted value.

## Result files

| File | Content |
|---|---|
| `results/main_<dataset>.jsonl` | Per-seed results of every method (Tables 3 and 7) |
| `results/ablation_gate_<dataset>.jsonl`, `results/ablation_comp_<dataset>.jsonl` | Per-seed gate-criterion and component ablations (Table 6, Fig. 3) |
| `results/per_user_npz/` | Per-user Recall and NDCG of every run, used for the Wilcoxon tests and Fig. 4 |
| `results/protocol_ml100k.json` | Sampled versus full-catalogue protocol study (Table 4) |
| `results/uncertainty_ml1m.json` | Per-user predictive variance, NDCG and activity (Fig. 5) |
| `results/uncertainty_ml100k.json` | The same analysis on ML-100K (not reported in the manuscript) |
| `results/tune_{a,b,c}.jsonl`, `results/best_cfg.json` | Every tuning run on ML-1M, Last.FM and Amazon-VG and the selected configuration per method and benchmark |
| `results/tune.jsonl` | An initial LightGCN depth check on ML-1M; configuration selection does not read it |
| `results/dcmi_timing.json`, `results/dcmi_log.txt` | Offline cost of the estimator |
| `results/tables.json`, `results/numbers.json`, `results/tab1_taxonomy.json` | Aggregated tables and the numbers quoted in the text |
| `results/train_activity.json` | Training interactions per user, per benchmark |
| `cache/<dataset>_dcmi.json` | Raw mutual information, null mean and standard deviation, z-score and density of every meta-path |
